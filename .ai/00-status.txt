SOMA — TECHNICAL BASE (read this first, together with GitHub Issues)

WHAT IT IS
Compact self-learning Minecraft agent. One world, one agent, no parallel worlds.
Decision model ~3.4M params (budget 10M), vector observations, no images, no LLM
in the game loop. Reward is multi-signal. Replay buffer on disk.
Spec source: idea.txt on the user's desktop.

TWO ADAPTERS, ONE BRAIN
bot/    Node + mineflayer, for VANILLA servers. Portable, no server-side install.
mod/    NeoForge 21.1.265 companion mod, for the user's create-aeronautics server
        (that server rejects vanilla clients, so a mod is the only way in).
Both speak the same newline-delimited JSON schema on TCP, so agent/brain.py does
not know or care which adapter produced the frame.

FAKE PLAYER (the hard part) — HOW IT IS DONE NOW
The agent is a REAL ServerPlayer: in the tab list, in the world, mob-targetable,
picks up drops natively. Getting there took four steps:
  1. new Connection(PacketFlow.SERVERBOUND) + an EmbeddedChannel. Connection keeps
     its channel in a private field - find it by TYPE via reflection, not by name.
  2. Claim every mod channel on that connection: read NetworkRegistry's private
     PAYLOAD_REGISTRATIONS and put all the ids into ChannelAttributes
     .COMMON_CHANNELS / ad-hoc channels. Without this NeoForge throws
     "Payload x may not be sent to the client!" the moment a mod pushes a packet.
  3. player.connection must be replaced with a ServerGamePacketListenerImpl built
     on OUR connection BEFORE placeNewPlayer(), otherwise placeNewPlayer touches
     the FakePlayer's original channel-less listener and NPEs.
  4. PlayerList.placeNewPlayer(conn, player, cookie) with
     CommonListenerCookie(profile, 0, ClientInformation.createDefault(), false).
Fallback if any of that fails: level.addNewPlayer(player) only (real entity in
the world, no tab entry).

DAMAGE / DEATH
  The agent takes real damage: mobs target it (verified: zombie->SOMA), hits land,
  fall damage is computed by hand (Entity.fallDistance only moves inside
  LivingEntity.travel()), lava burns, starvation drains, regen heals above 18 food.
  On death the mod fakes the vanilla death flow (a dead fake player has no client
  to press the respawn button): inventory restored, food reset, respawn at spawn.

MOVEMENT
Real locomotion, not teleport: accelerate toward the target, apply friction and
gravity, then player.move(MoverType.SELF, delta) so collisions, step-up, fall
distance and step sounds behave like a normal player. setPos() is what made it
look like a floating armour stand - never use it for locomotion.
Movement speed ~0.13 blocks/tick (2.6 m/s), jump 0.42.

PROTOCOL (schema v1), one frame -> 3450 float32
  self 32 | grid 512*6 | ent 12*10 | inv 41*4 | ev 10*5 | meta 12
All relative to the player and rotated into the player's frame (translation and
rotation invariant). Categorical ids go through FIXED hashed embeddings (4096
blocks, 2048 items, 1024 entity names) so a 248-mod pack cannot shift the space.
Candidate = one admissible action; the mod/bot advertises <=48, the brain answers
with an INDEX. 16 features per candidate.

MODEL (agent/model.py) — 3,428,097 params, fp32, ~14 MB
  encoder 3450->768->192 | temporal 6*192->384->192
  Q head (192+16)->128->1 per candidate | V head | aux dynamics head
The encoder is trained ONLY by the auxiliary loss (predict next latent); the RL
loss uses detached latents. That keeps policy learning cheap and stable.
Trainer publishes model.npz.tmp.<pid>.npz then os.replace; brain reloads on mtime.

REWARD (agent/reward.py), clipped to +-3
  new block type, new item type, new chunk (log-damped novelty), damage, death
  (-3), idle, time cost (-0.005/step), pickups.

BUGS FOUND AND FIXED (do not reintroduce)
  1. Never cast Gson numbers blind: (int)(double) o throws ClassCastException.
     Use ((Number) o).intValue().  This silently broke every mine/use/place.
  2. np.savez appends .npz unless the filename already ends with it - a temp file
     named model.npz.tmp.123 would be written as model.npz.tmp.123.npz and the
     os.replace would fail. Always end temp names with .npz.
  3. Division by zero in enc.py when an entity has no health (hp = -1): always
     clamp with max(x, 0).
  4. One malformed frame must never kill the brain - wrap on_frame in try/except.
  5. ServerLevel.getBlockState resolves and joins a chunk future on every call.
     Go through the cached LevelChunk (and skip the fallback) - 33 ms -> 2.6 ms.
  6. pkill -f user_jvm_args kills the SSH shell itself (its own cmdline matches).
     Use the pgrep -x java + ps -p $p -o args= loop.
  7. An entity without health breaks enc; a Double in a %d breaks String.format -
     always count format specifiers against arguments.
  8. THE BIG ONE: a FakePlayer never ticks, so Entity.tickCount stays 0, and
     Entity.isRemovedOrRecentlyCreated() is (tickCount == 0). LivingEntity.hurt()
     rejects ALL damage on a "recently created" entity - mobs happily target the
     agent, swing at it, and nothing happens. Fix: call player.baseTick() every
     tick (and bump tickCount if it did not move). Symptoms looked like "the mob
     pack is not doing damage", the real cause was an entity that was never alive.
  9. Entity.setInvulnerable() is a different flag from Abilities.invulnerable and
     is checked first - clear both.
 10. placeNewPlayer() reloads the player NBT from disk: give the starter kit
     AFTER it, otherwise the inventory is wiped.
